8deec33 的本轮原验证保留三个独立失败边界。两个 Windows full suites 均在 CodeBuddy 原生认证夹具的目录枚举/内容数量复合断言失败；旧日志未打印 ReadDir 错误或 entries，因此不能倒填为实际复制了业务配置，或将后续受控共享模式实验当作旧运行轨迹。原 32 mandatory 和两个独立 DACL/pin roots 的通过也不能覆盖 full suite 失败；owned_lifetime 在前置断言停止，后面的 refresh 断言尚未执行。

原 T15 的最小修复移除目录创建句柄不需要的 DELETE desired access，仍禁止 delete-sharing 并全程保持目录 pin。创建时 owner/protected DACL、读取源、凭据文件刷新替换、普通 provider 目录读取、清理与原隔离 oracle 保持。新增原生有/无 DELETE 的受控反例分别证明普通 ReadDir 兼容性和 rename 仍受禁止；机制证据与历史失败分开。两个原生 Windows 版本必须实际执行这些控制，交叉编译不能代替。
