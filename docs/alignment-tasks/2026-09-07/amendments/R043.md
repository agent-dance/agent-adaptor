## 连接分流与父执行隔离

本修订替代 R042 中“其他 foreign thread/turn 一律拒绝”的连接分类假设，保留
其语义准入边界。合法外部线程不等于损坏的父协议；可能是直接子线程、后代或
其他订阅线程，无须先证明它最终成为当前父 spawn receiver 才能保留为 Raw。

- 只在已知正式 scoped methods 上解析 scope/必要 envelope，foreign 通知只留
  完整 Raw，不进入父 Text、Transcript、Usage、Todo、failure 或 terminal。
- 分流在 duplicate-terminal 判断前发生；child 的 `turn/completed` 不能被当成
  父线程第二个终局。当前父 wrong-turn/duplicate、malformed scope/status
  与已知身份冲突继续严格处理。未知方法不靠递归 JSON 猜 scope。
- 结果快照冻结与公开终局使用同一通知封账边界；封账后的尾帧只保留实际 Raw，
  不能迟到修改错误、checkpoint 或观察事实。provider terminal 只是关闭正常
  语义与查询准入，不能提前吞掉封账前必需的验证及已准入查询收尾。
- 不为外部语义建立 unresolved-ID 队列，不缓存或重放 child 内容，不从 status
  推断身份，不因此触发元数据 RPC。保留已有正式 `thread/started` metadata
  的严格 parent/role 关联及两种证据顺序；非本父 metadata 只留 Raw。

## 正式角色补证与生命周期

仅当前父、当前 turn 的正式 spawn receiver 可触发私有 `thread/read`，显式
`includeTurns=false`。已有一致完整 metadata 不重复查询。关联仍须同时满足
返回 ID、正式 direct parent/role、当前 spawn receiver 和唯一 resolved catalog。
首次查询返回的错误 ID、错误 direct parent 或内部角色矛盾只拒绝并锁定 requested
receiver，报告安全 invalid/unresolved notice，不给错误返回 ID 登记身份；首次
公告中自相矛盾的角色同样不是已接受身份。首次无效观察不提升为父执行失败。若新 metadata 与此前已严格接受的 direct-child
身份或角色矛盾，则在同一合并点立即记 protocol failure，不能等下一条 status
偶然触发；这种已知身份冲突不得被后到成功清除。缺失/unsupported/超时等观察
不可用保持可观察 `capability_unresolved`，不能伪造完成或令健康父业务失败。

每轮至多 128 个独立 receiver、一个 worker；单次查询最长 1 秒，父终局后总
收尾上限 2 秒（含最后 100ms 的取消/join 窗口），不按队列长度倍增。任一已发出
查询因 context 结束而放弃等候响应（含单次 deadline 与总收尾主动 cancel），
且连接仍将保留时，停止余下查询；该 resident 到正常退役前暂停新增可选查询，
公告通道继续可用，避免依赖库保留的未答 pending 跨轮无限累积。唯一 RPC reader
的同步 callback 不能等待 RPC 或 worker。父 provider terminal 关闭查询准入，由 process owner
在公开终局前结算已准入工作；spawn 完成仍来自父 collab 状态，不等 child 工作
结束。取消/Close 后 worker 必须在卸下本轮 observer、冻结 Result/Raw、释放
turn lock 或下一轮开始前 join；原取消/协议/transport 主因不能被查询次因覆盖。
元数据连接关闭不能遮蔽已发生的正式协议解码错误；在已有运行错误路径上，
进程非零退出的实际 `*exec.ExitError` 必须保留在错误图中，不能仅折算为
Response 的 exit code。普通非零退出沿用既有 Driver Response.Failure 语义。
这些失败均保留部分审计，且不得产生健康 checkpoint。

RPC 的同步管道写入不保证受 context 取消中断。若写入阻塞导致 worker 无法退出，
owner 必须通过既有有界 transport/process cleanup 解阻并 join，保留实际 cause、
部分审计和无健康 checkpoint，不复用坏 writer。仅 waiter 超时且 worker 已退出、
共享 transport 健康时才可按观察不可用处理。迟到响应不应用到旧 Result 或新 turn；
Raw 只声明实际捕获，不将 worker join 冒充未到响应已经排空。
