# R044：Codex 子线程元数据可用性的有界恢复

`731a908` 原 T29 SubagentCatalog 和 T30 CancelPartial warmup 失败继续保留。
后续仅增强观测的 Codex Luna 单场景，将真实发送的 `thread/read(includeTurns=false)`
与同 ID 正式 `-32603` 应答关联，命中官方 session metadata 读取及 `is empty`
字面错误类别。该补充运行还缺少预期 nonce，原因独立未知；不得倒填此前联合断言
的失败分量，或把 metadata 修复宣称为答案内容修复。

固定官方 Codex 0.153.4 源码说明，子线程 spawn 完成不是 SessionMeta 已持久化
的屏障：recorder 先创建文件，再写入并 flush；读取路径遇到已存在但不可解析的
元数据会直接返回 store error。正式 `is empty` 只表示未找到可解析 SessionMeta，
不证明物理文件为零字节。无凭据、无模型的私有 RPC 控制证明该路径可以恢复，
但不保证某个真实文件一定会恢复。

## 精确恢复范围

仅对 R043 已准入的当前父/当前 turn 的单一 spawn receiver，在第一次只读查询
正式返回以下全部条件时，记录一次恢复候选：RPC code 为 -32603，消息以
`failed to read thread: thread-store internal error: failed to read session metadata `
开头、含正式 `: rollout at ` 分界并以 ` is empty` 结束。路径与错误内容不得成为
identity 或角色证据，也不得输出到安全 Notice。未知错误、其它 RPC code/类别、
成功但不完整或无效的 metadata、timeout/取消/transport 错误均不新增恢复资格。

provider terminal 中的 `seal()` 仅结束准入，不能放行恢复。process owner 在正常
父终局后做有界资格快照：正式状态 Completed，无 turnFailure、protocol/caller
错误，无已观察到的 Close、EOF 或 Wait 结束；只保留在该决定点仍缺乏完整合法
角色且未被拒绝/判冲突的候选。之后由原同一个 worker 对每个候选最多再调用一次
metadata-only read。不得等待 child 任务完成、sleep 猜时机、重放 prompt 或新增执行入口。

保留最多128个独立 receiver、同一时刻一个 RPC；每 ID 最多两个发送，且每 ID
只发布一个最终 worker result，不能把结果队列需求增加为256项。原单次查询1秒，
父终局总收尾2秒（包括最后100ms取消/join）不变，首轮待处理和恢复共用此上界，
不得按ID数或恢复轮次倍增。context-abandoned 查询不恢复，既有 resident 可选查询
暂停规则不变。取消/Close/EOF与放行竞态仍走原有关闭、join及真实cause保留路径。

最终响应继续通过原 requested ID、direct parent、role及唯一 catalog 的严格合并。
首次无效事实的粘滞拒绝和已接受身份矛盾的即时 protocol failure 均不能被恢复抹去。
二次仍不可用只产生 unresolved；完整首错及应答保留在 Raw。公开终局前 join、
通知封账、结果冻结、下一轮隔离、同步写阻塞的 owner transport 关闭及失败无健康
checkpoint 合同不变。
