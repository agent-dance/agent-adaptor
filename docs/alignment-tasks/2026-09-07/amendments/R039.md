# R039：managed clone 的同名异源覆盖边界

R038预审与原T06的确定性反例发现：copied目录的来源marker落在真实ManagedRoots内时，原CompatibilityTargets对相同key/runtimeName直接保留，正式ReconcileProfileSkills允许旧source A→新source B，EnsureSkillTarget随即删除旧树。反例观察到两条路径返回nil，正式reconcile删除user.txt。该事实来自合成离线fixture，不倒填8db的live失败原因。

来源marker证明origin，不证明实际内容/权限。沿既有copied-prune保守合同，对不可证明安全的copied异源覆盖，在兼容视图及正式reconcile破坏前返回profile.ErrUnsafe。保留same-source普通树全部实际bytes/modes/未知附件，并继续计入fingerprint；合法已证明symlink的正式替换保持。不得用ManagedRoots=nil、换runtimeName或跳过正式reconcile规避原反例。

原T06在R038工作树追加两个精确写文件：internal/skillruntime/compatibility.go与profile_reconcile.go，测试仍限既定profile_clone_test.go和alignment_managed_clone_test.go。无其他owner重叠，无新任务/要求、公共API、manifest格式或复制框架。copied clone保留既有source marker；source manifest不搬迁，目标绝对路径仍由正式reconcile登记，避免persistent staging搬移失效。

红例原文件/命令/日志与独立预审保留在外部E/repairs/R038-T06和E/reviews/R038-T06。实施后须非作者复验，再合流统一使用文档/CHANGELOG。同新S的G05、全部B06与G06要求、47任务/96要求/45处置/G05九依赖和原完整命令均不变。
