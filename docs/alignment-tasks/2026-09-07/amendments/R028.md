# R028：使用官方修复的 fuzz 工具链

本修订继续执行用户“全部修复”和按建议修复全量 CI 的授权。SDK 公共语义、最低消费者版本和原验收命令不变。

## 原失败与独立机制证据

`75a84c8b7a62e4bcdcca2fe9e2e31c8670d0fcb9` 的普通 Go 五个job、三平台专项与原生 T26 通过；T25-V01 至 V08 通过，V09 的 `FuzzSniffArchiveFormat` 在30秒、847052次执行后报 `context deadline exceeded`，没有crash输入或源码修改。原失败日志保留在分支外部验收的 `attempt-75a84c8/t25`；普通CI同型fuzz通过不能关闭这次失败。

[Go官方75804](https://github.com/golang/go/issues/75804)及[修复提交5a957dc](https://github.com/golang/go/commit/5a957dc766aed011cdfe7c953987a2ff86c0829c)说明：父context先发布deadline再取消子context，协调器只比较child.Err时可把正常停止记为失败。Go1.27正式实现同时比较parent.Err。

独立机制复现通过显式临时overlay在parent发布与child取消之间放置屏障，保持原fuzz目标及30秒命令：旧判断看到parent deadline/child nil后返回deadline，新官方判断在同一窗口正常通过。overlay、源文件hash与两份完整日志独立归档；它们不能当正式验收，也不能倒填原CI未记录的内部调度轨迹。

## 工具链与门禁

新增 `.github/go-version` 固定官方Go1.27.1，普通CI、三平台专项和T25/T26使用该版本；它包含官方修复且已于2026-09-01正式发布。保留 `go.mod` 的Go1.26.8最低版本，新 `minimum-go` job直接读取它并执行完整test/vet。

正式验收不修改工具链，不吞deadline、不自动重试、不用执行次数代替原30秒预算。原collector/skip策略/9个fuzz目标/全量race/20轮重复/S1–S9/四Driver conformance及live关闭门继续。各项重新记录相同源码SHA与实际Go版本；G05、T25、T26必须全部通过后才封账，T27–T30/G06独立保持。

任务包revision27仅向G05精确追加 `.github/go-version`，保留47任务、96要求、原9个依赖、原3条G05命令、真实G04基线及完整diff路径。未新增生产实现所有者或改变历史worker结果。
