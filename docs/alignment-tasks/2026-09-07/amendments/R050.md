# R050：CodeBuddy 正式工具错误与延迟调用诊断

42b1127 的原 G05、11 个 CI job、T25/T26 和 Claude/Codex Luna/Cursor 完整 live 均已独立接受；CodeBuddy 的原目录场景在 481.62 秒达到原定 deadline。其五次正式 DeferExecuteTool 参数均精确匹配 VERIFY，外层 tool_result.is_error 为 false，但宿主 callback 总数为零。本轮十个其他真实场景及 conformance 通过，完整矩阵仍为 needs_rework。旧失败、原检查、84/96 的当前独立接受边界及 G06 未通过状态保持。

独立静态与受控方法验收发现一个不同于未知 live 原因的明确缺陷：官方 CodeBuddy 2.157.0 在 MCP isError 为 true 时，正式 stream-json 输出可同时包含外层 is_error=false 与 _meta.rawResponse.is_error=true。当前 Capability、Transcript 与 typed ToolResult 三条路径只读取外层，漏掉正式失败信号。原 T15 在五条精确路径内修复，三条投影使用同一私有规则：外层 true 或精确内层 bool true 均是工具失败，内层 false 不得抹掉外层失败。不从正文、tool_error_code、字符串或任意嵌套 JSON 猜测失败；未知 rawResponse 形态不自动成为整轮失败。原外层畸形标记保护保留，任何新增已识别字段的畸形处理必须有明确的局部测试。

单个工具错误不自动改写整轮 terminal、RunError 或 checkpoint 的健康判定。Raw 原字节、原 Transcript 内容、exactly-once typed result、scope/parent 关联、Todo 仅成功确认、已有主因与取消边界保持。修复先保留最小正式 frame 反例，再在原作者固定 SHA 完成原四检查及必要 vet，并由非作者复验。

另行诊断不能冒充上述缺陷是本轮 live 根因。固定 S42 的首次定向诊断在原 8 分钟时限失败，三次精确 Defer 调用的正式正文均匹配官方 not-indexed 模板，宿主 callback 为零；正式结果未携带 rawResponse，不能据此补造内层错误值。该新观测不倒填原矩阵的五次调用。官方精简 init 可报告配置的 server connected 而不列出其工具，因此未列出 echo 不能证明 inline 加载或实际网络连接；成功 MCP 与内部拒绝也可输出相同正式 frame，生产 parser 不能猜正文。后续连接层诊断只增加闭集 HTTP 分支与正式 MCP 方法计数，原 fixture、模型、prompt、8 分钟时限与 oracle 保持，不记录凭据或请求正文。完整原矩阵失败保留，定向诊断不替代完整验收。
