# R012 — 主动执行预算封账与原子持久化边界

B03 独立预审固定 G02 75332ea502b42ce40229840f3eae75c103b5a9f2 发现 C02 合同矛盾：要求预算涵盖 Finalize 返回，又要求预算失败不改变旧记录。既有 Store.Finalize 只有 error，无提交确认回调；合法 Store 可以先原子提交，再延迟返回。延迟期间预算到期后，SDK 不能无损撤销已提交记录，也不能声称从未提交。证据位置为 memory/store.go 的原子写入及 internal/engine/session.go 的 Finalize 调用；这属于冻结设计预审发现，未冒充未来预算实现的实跑失败。

修订只明确主动执行阶段的结束点，不新增 Store 接口、执行入口或回滚机制：

1. 预算从首次资源准备前开始，涵盖 Driver、fallback、终局 schema、lease/健康条件复核。健康候选在进入唯一 Thread Persist 之前封账；无状态候选在对应最终健康判定后封账。没有健康 checkpoint 的 Thread 仍拒绝持久化。最终成功仍须等 Finalize 完成，封账不是成功。
2. 私有 Controller.FinishExecution() error 在计时器同一短锁中检查 parent/child 已有 cause，按单调 Now 结算 running 段；paused 不重复扣时。若余额已耗尽，登记 expired 并返回 cause，不能靠迟到 timer 尚未调度抢先成功。否则停 timer、推进 generation、清 token 并永久封账。首次结果缓存，重复调用不重新计时或改结论；之后 parent 取消仍通过原 context 传播。该方法不得回调 core。
3. Core 在同一终止归因短临界区检查既有具体失败并与 FinishExecution 排序，不能无锁检查后跳过竞态。FinishExecution 返回 error 或已有终止候选时不调用 Persist。Stop 继续只做错误/cleanup 收尾，不能重新结算而制造覆盖既有主因的预算错误。
4. 封账成功后 Finalize、其返回延迟及资源 cleanup 不扣主动预算。Finalize 仍接收原可取消 context；WithTimeout、parent deadline/Cancel、Agent.Close 和 lease 校验不失效，不使用 detached context 持久化。Finalize 失败保留完整部分 Result 和原 cause，不能因为封账而返回成功。已经原子提交的健康状态不做不安全回滚；父取消在提交前的协作责任与提交后的既有事实须区分，不能承诺撤销任意 Store 的已完成副作用。
5. 必需反例：余额已到但旧 timer 尚未执行时封账拒绝/零 Finalize；封账先赢后手工触发旧 timer不得超时；Store 提交后延迟返回跨过原预算仍无 active timeout；Finalize 返回错误仍失败；原 parent context 可取消；stateless、缺 checkpoint、schema 失败、已有 primary cause、并发 Ask release 与封账均覆盖。私有时钟测试用 barrier/fake clock，不能靠 sleep 的运气。
