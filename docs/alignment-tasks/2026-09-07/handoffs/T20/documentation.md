## Consumer-visible contracts independently exercised

- Claude result-only success/failure/schema and message-stop completion close one-shot stdin, retain all raw bytes including the post-EOF whitespace/stderr suffix, and deliver one final core envelope. Intermediate tool-use stops retain stdin for real Question/PlanReview/Permission control responses. Each successful response is compared with an independent complete wire object: subtype, request_id, toolUseID, original updatedInput and Question answer, with no synthetic fields. Public Kind is checked. Ordinary Permission without schema also has a real allow roundtrip on Run/Stream. Nil legacy matrices cover explicit Ask/unset with WorksWithHITL true/false and ordinary policy rejection before resources, including real DecisionCapableSink replies in eligible explicit-Ask cases.
- A default resident Thread executes two prompts on the same PID. Compatible rich → native schema batch → rich transitions keep the same active store record and checkpoint, actually launch and reuse the prewarm process, and deliver each prompt once. Actual process liveness at startup detects concurrent writers. `WithSpawn` does not promote that turn's process. Model, workspace and append changes still reject ResumeOnly before prompt delivery.
- Interrupted Claude/CodeBuddy/Codex processes retain their observed Raw/Transcript/Usage through RunError, with cancellation/deadline identity intact and the complete previous store record unchanged. Claude Text is empty without its authoritative result field, as already documented; CodeBuddy's partial fallback and Codex's observed assistant text stay available. Nonzero exit, malformed/missing terminal and a terminal followed by nonzero exit cannot persist a healthy checkpoint.
- A hand-written SPI producer supplies distinct Text, Summary, Raw streams/terminal, Transcript, Usage, Model, Provider, Metadata and observed Services. Every audit field, full Transcript and Service item, metadata and Terminal.Event has a separate literal expected value; Run and Stream also return equal audit values, including validated structured output in the success case. Provider success before workspace cleanup or lease-finalize failure does not emit an early successful public terminal, with and without an attached Event source. Healthy committed state survives subsequent cleanup failure.
- Static schema/policy rejection yields empty closed Events and zero resource/Driver calls. An admitted resource failure has one core lifecycle and keeps its ordinary wrapped pre-Driver error. Close deadline failure is bounded; new Agent/Thread calls remain closed and retry is idempotent.
- Dedicated+WithTools writes an actual nonce-bearing provider session file, closes Agent A, and resumes with a new Agent B using the same source/config/identity/key. The second prompt does not contain the nonce. The original token must first authenticate an actual loopback initialize request and, after Close, the same token must be rejected or the listener must refuse connection. Timeout and unauthenticated 401 are not revocation evidence. Tokens stay only in private temporary control files/memory and never appear in logs. Endpoint credentials rotate; the source is untouched and not reseeded, and persisted transcripts survive. Existing regular MCP file modes are preserved, while actual external mode/Tools Revision changes reject resume. Missing historical files cause explicit ResumeOnly failure; default continue-or-start performs one rejected-resume/fresh fallback and archives the previous record only after success.
- Same-process and subprocess contenders cannot claim the same execution profile. Full identity fields and delimiter/NUL/Unicode cases receive distinct namespaces; canonical source aliases share the same claim. Unsafe marker/version, symlink and POSIX control-file permissions are rejected before prompt delivery. Unclean host-process exit leaves active state requiring offline recovery. Default/Native/CloneFrom/CloneNative hosted profiles remain temporary. A real MCP-path IO failure prevents Close from releasing ownership until cleanup succeeds; a closed predecessor never rewrites a successor generation.
