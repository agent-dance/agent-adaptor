# T20 independent lifecycle QA

This task adds tests only. Public behavior, root/SPI declarations, goldens and dependencies are unchanged. G05 owns central documentation integration; the applicable contracts are C01–C04 and R001–R016. R017 changes the accepted base and native fixture coverage, not this task's ownership or test requirements.

The fixtures call public `adaptor.New`, `Agent`/`Thread.Run` and `Stream`, with real child processes emitting hand-written Claude, CodeBuddy, Cursor and Codex app-server protocol. The child is the current Go test executable, selected before the existing e2e TestMain. Each fixture receives a private HOME/USERPROFILE/XDG_CONFIG_HOME and cleared provider roots; Native/Default fixtures resolve their actual default directory under that private home. No real provider binary, credential file, paid call or external network service is used. Tool gateways bind loopback only. Machine-specific Go installation/cache paths belong to the external execution harness and do not appear in committed tests.

## Consumer-visible contracts independently exercised

- Claude result-only success/failure/schema and message-stop completion close one-shot stdin, retain all raw bytes including the post-EOF whitespace/stderr suffix, and deliver one final core envelope. Intermediate tool-use stops retain stdin for real Question/PlanReview/Permission control responses. Question answers and approved plans are checked in the provider's received response JSON.
- A default resident Thread executes two prompts on the same PID. Compatible rich → native schema batch → rich transitions keep the same active store record and checkpoint, actually launch and reuse the prewarm process, and deliver each prompt once. Actual process liveness at startup detects concurrent writers. `WithSpawn` does not promote that turn's process. Model, workspace and append changes still reject ResumeOnly before prompt delivery.
- Interrupted Claude/CodeBuddy/Codex processes retain their observed Raw/Transcript/Usage through RunError, with cancellation/deadline identity intact and the complete previous store record unchanged. Claude Text is empty without its authoritative result field, as already documented; CodeBuddy's partial fallback and Codex's observed assistant text stay available. Nonzero exit, malformed/missing terminal and a terminal followed by nonzero exit cannot persist a healthy checkpoint.
- A hand-written SPI producer supplies distinct Text, Summary, Raw streams/terminal, Transcript, Usage, Model, Provider, Metadata and observed Services. Public Run and Stream return equal audit values, including validated structured output in the success case. Provider success before workspace cleanup or lease-finalize failure does not emit an early successful public terminal, with and without an attached Event source. Healthy committed state survives subsequent cleanup failure.
- Static schema/policy rejection yields empty closed Events and zero resource/Driver calls. An admitted resource failure has one core lifecycle and keeps its ordinary wrapped pre-Driver error. Close deadline failure is bounded; new Agent/Thread calls remain closed and retry is idempotent.
- Dedicated+WithTools writes an actual nonce-bearing provider session file, closes Agent A, and resumes with a new Agent B using the same source/config/identity/key. The second prompt does not contain the nonce. Endpoint credentials rotate; the source is untouched and not reseeded, and persisted transcripts survive. Existing regular MCP file modes are preserved, while actual external mode/Tools Revision changes reject resume. Missing historical files cause explicit ResumeOnly failure; default continue-or-start performs one rejected-resume/fresh fallback and archives the previous record only after success.
- Same-process and subprocess contenders cannot claim the same execution profile. Full identity fields and delimiter/NUL/Unicode cases receive distinct namespaces; canonical source aliases share the same claim. Unsafe marker/version, symlink and POSIX control-file permissions are rejected before prompt delivery. Unclean host-process exit leaves active state requiring offline recovery. Default/Native/CloneFrom/CloneNative hosted profiles remain temporary. A real MCP-path IO failure prevents Close from releasing ownership until cleanup succeeds; a closed predecessor never rewrites a successor generation.

## Limits and existing evidence

Exact OS-unlock-success followed by lock/root CloseHandle fault injection is not available through public Agent APIs. T20 independently proves cleanup failure before release and predecessor/successor behavior; the existing T04 `internal/hostedprofile/claim_test.go:TestReleaseAfterUnlockFailureDoesNotTouchSuccessor` remains referenced owner evidence and is not counted as a new T20 pass. Native Windows no-delete-sharing/DACL/rename behavior remains T26's responsibility. POSIX permission assertions are explicitly OS-specific; Windows is not certified by compilation or Darwin execution. Linux and all paid/native provider scenarios remain their respective B06 tasks.

Claude's startup transport lacks the CodeBuddy/Codex initialization acknowledgement. A child dying before reading a prompt may still have received it in its stdin pipe, so the test requires no unsafe replay and an observable failure. It does not mislabel that public observation as the private pre-write failure seam. CodeBuddy's failed handshake safely retries once; Codex's failed handshake uses one one-shot fallback plus an empty prewarm, still one delivered prompt.

The independent expectations do not adopt internal failed-checkpoint persistence, detached checkpoint writes, native Permission schema claims, recursive protocol guessing, or alternate execution APIs. Existing owner tests and historical live results are not counted as independent QA. Final platform, Go version, exact base/head, commands and nonzero counts belong to the post-commit result/evidence artifacts.
