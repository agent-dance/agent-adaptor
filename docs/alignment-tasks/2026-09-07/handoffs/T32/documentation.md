# T32 AG-UI publication snapshots (R019)

Previously, a returned Subagent ActivityDelta `/toolCalls` value shared the tracker's backing slice. A later `subagent.tool_call.end` changed the already-delivered status from `running` to `completed`; ordinary concurrent `json.Marshal` raced with that write. T21 observed this through its real Claude fixture → Local Service → parent Agent → AG-UI stream. Its original fixed-head race and snapshot logs remain unchanged in this handoff's evidence.

The bridge now copies its activity content and tool-call structs at publication and recursively copies the Args/Result/Error JSON containers. Each snapshot/delta and flush error value owns its data independently of the translator and other published fields. Callers can retain or serialize delivered events while subsequent translation and CloseResult continue; consumer edits cannot write back to the tracker. The existing public Event copy operation already isolates incoming SubagentUpdate JSON containers. The bridge reuses that contract for nested map/slice/array copies and explicitly copies its private structs; it does not serialize/parse JSON to clone values. Named map/slice types, json.RawMessage, byte slices, json.Number, full uint64 values and nil versus empty containers retain their types and values.

No wire fields, tool or parent identities, ordering, status rules, cancellation/flush behavior, terminal authority, Raw data, public declarations, golden files or dependencies change. No consumer lock, alternate stream, Driver interpretation or policy is added. A tool delta recorded with `status: running` now continues to serialize as running after the next completion event; that next delta independently reports completed.
