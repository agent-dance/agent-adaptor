## Public changes and reproducible use

`DelegationRequest.ActiveExecutionTimeout` and `DelegationPolicy.MaxActiveExecutionTimeout` are independent of the existing wall-clock `Timeout`/`MaxTimeout`. Both accept zero (no active bound) and positive durations; negative values fail before BeforeDelegate or I/O. The effective bound is the minimum of positive request/maximum values, or the only positive value. Registry registration rejects a negative maximum. For example, a 100ms request with a 200ms maximum receives 100ms, whereas both zero means no active bound. Existing Timeout clamping and defaults are unchanged.

Each Delegate, including continuation on the same TaskID, gets a new private controller. BeforeDelegate, discovery, send/stream/poll, retries and recovery share this controller; completion calls FinishExecution before cleanup. AfterDelegate and best-effort CancelTask each use an independent five-second context. A Member's Ask pauses only the Member's own budget; no `WithPolicy` is injected into the Member. A delegator with 100ms therefore expires while a Member is asking, even though the Member's own one-hour budget is paused. Known TaskID is seeded from Message.TaskID, so cancellation before new I/O can still cancel the known remote task once. Partial artifacts are collected before cleanup; remote cancellation failure adds only `remote_cancel=failed|timeout`.

`DelegationError.Cause` is excluded from JSON and `Unwrap()` exposes the original Go error graph. Existing Code is authoritative. Local root RunError.Reason is selected before cancellation/deadline secondary causes; partial Text, Summary and Raw retain their original meanings through the original RunError in Cause. Public text/artifact projection remains subject to existing hosttool exposure. Active budget errors retain a trustworthy positive typed Limit when present; an incoming active code without limit matches ErrActiveExecutionTimeout without inventing a typed limit. Frozen wire fields are validated as a complete control object, and invalid code/state/number/extra controls fall back to remote_failed/remote_cancelled with a safe diagnostic. Duration milliseconds round upward and saturate before multiplication.

`Service.AttachRun` now returns `BindEvents` and `Events=nil`. The single bound publisher accepts cloned events into the leader's unique sink, including synchronous bounded observers, before EventBus.Publish. The former EventBus→core pump is removed. Capability and todo facts remain typed `adaptor.CapabilityInvocation`/`adaptor.TodoUpdated`, with no duplicate SubagentUpdate projection. Config.Observe remains a lossy component UI callback; it must not be used as the recorder source. A local recorder and a remote store are optional.

`EventBus.RunEventsBound(runID)` is exact, monotonic proof of successful binding. Attach alone, nil binding, ordinary Publish and failed binding do not establish proof. Detach/ClearRun keep proof while revoking publication; old publisher calls return context.Canceled. Consequently the existing subagentstream.Merge recognizes a real Service-bound stream even after teardown and does not duplicate events.

Request/Event gain ScopeID and ParentScopeID; Event gains Capability, Todo and Source pointers plus the two new existing-kind constants. Relayed scope/tool/invocation IDs use the C03 exact reversible JSON-array/Base64 tuple with distinct tags. The immediate upstream source records original RunID/Sequence/time/thread/turn and original scope/tool/invocation coordinates; recursive Upstream retains prior relay provenance. ParentToolCallID uses its actual remote ParentScopeID when present, otherwise the request's actual parent coordinates. Empty remote root scope still receives a domain. Replay deduplicates identical `(remote RunID, Sequence)` payloads within the delegation and emits a safe invalid_payload drop on conflicting reuse. Retries/recovery keep the same map; different delegations do not share it. Local formal events pass the accepted B03 closed decoder without JSON normalization that could repair invalid UTF-8. Tuple expansion past local 2048-byte identity bounds and source depth nine explicitly degrade; no truncation/hash or ignored publisher rejection.

BeforeDelegate must succeed and leave its context healthy before host-lifecycle outer Started. That fact precedes discovery and all I/O. After primary settlement and AfterDelegate, the final result is recorded, one outer terminal is emitted, and the buffered delegation terminal is flushed. After failure can therefore never yield an earlier Completed fact. A publisher rejection becomes observable infrastructure failure or secondary cause under an already fixed primary.

## R016 same-Stream terminal qualification

Local Send now calls Runner.Stream once, drains it, and reads Result on that same Stream. SendStream and bounded cancellation drain use the same private O(1) collector before event filtering. Error alone still determines failure. A non-nil RunError carrier always wins, including unknown or empty Reason. Only bare errors may use a matching nonempty Meta.RunID and a closed stream with exactly one last typed Failed RunFinished carrying a known eight-code Reason. Body/provider RunID may differ or be empty; duplicate terminals, terminal followed by any event, unknown/empty Reason, false Failed or wrong attribution invalidate the hint. No arbitrary payload is stored, no new failure or Result is manufactured, and original error/Result objects and graphs remain intact. Cancelled/approval/deadline hints never extract a parent's active Limit. Without a usable hint the prior bare active/deadline/cancel fallback remains unchanged.
