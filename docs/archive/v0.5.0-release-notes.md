# agent-adaptor v0.5.0 Release Notes

This release sediments host-integration patterns that every production
host had to write manually on top of v0.4. The full design rationale
lives in [`v0.5.0-host-integration-plan.md`](./v0.5.0-host-integration-plan.md);
this document is the operator's view: what changed, what to do about
it, and what to copy.

> **TL;DR for upgrading hosts**: 2 breaking changes, both with 1-line
> migrations. Average upgrade time per host is **30 minutes**, the
> majority spent rewriting one method on the host's `SkillProvider`.

## What changed

| Area | What | Compatibility |
|---|---|---|
| Public errors | All `Err*` sentinels centralised in `errors.go`; new docs at [`docs/public-errors.md`](../public-errors.md). 5 typed-error predicates (`IsRunEnded`, `IsDecisionExpired`, `IsSessionBusy`, `IsSessionIncompatible`, `IsSkillKeyConflict`). | Additive |
| `ErrSkillsNotEnumerable` | Removed. Non-enumerable providers simply don't implement `SkillCatalog`; `Admin.ListSkills` reports `SkillSyncMode = SkillSyncUnsupported`. | **Removed sentinel** — match `Mode == SkillSyncUnsupported` instead |
| `SkillProvider` | Re-designed: `List(ctx, tenantID)` → `GetSkills(ctx, keys)`. Per-key resolution makes large remote stores first-class. New `SkillCatalog` super-interface for hosts whose catalogue is enumerable. | **Break** — see migration cookbook §1 |
| `SkillSource` | Marker promoted from private (`isSkillSource`) to public (`SkillSource()`). Hosts can now define custom source types. Built-in: `SkillFromPath` / `SkillFromFS` / `SkillFromInline` / `SkillFromArchive`. | Theoretically a break (private marker), but third-party implementations were structurally impossible before |
| `SkillFromArchive` | New built-in source: zip / tar / tar.gz with magic-byte sniffing, zip-slip protection, decompression-bomb caps, content-addressed cache. Replaces the originally-planned `SkillFromURL` (URL is now one of three reader factories: `ArchiveFromBytes`, `ArchiveFromPath`, `ArchiveFromURL`). | Additive |
| `LocalSkillsFromDir` / `SkillsAsRefs` | New helpers for "every subdirectory under root is a skill" (`/opt/skills/...` style) deployments. | Additive |
| `CallerIdentityFromContext` / `WithCallerIdentity` | New helpers exposing the `AgentIdentity` SDK injects before `SkillProvider.GetSkills` / `SkillCatalog.Catalogue` invocations. Public, gRPC-/OTel-style; do NOT read raw context keys. | Additive |
| `RuntimeServiceManager.ReleaseByLabels` | New required method: release all services whose `Metadata` matches the given labels. Closes the gap where containerised hosts had to bypass the SDK after process restarts. | **Break** — embed `runtimeservice.NoopReleaseByLabels` for a 1-line migration |
| `sessionrecorder.PendingDecisions` | New: derive the pending-HITL list from existing history. **One-shot snapshot**, O(n). | Additive |
| `sessionrecorder.PendingTracker` | New incremental tracker, O(1) per event, thread-safe. Use for long-running session loops where re-deriving on every event would be O(n²). | Additive |

## Migration cookbook

### 1. `SkillProvider.List(ctx, tenantID)` → `SkillProvider.GetSkills(ctx, keys)`

The new method is **per-key resolution** rather than full-catalogue
enumeration. Below are the canonical patterns; pick the one that
matches your deployment.

#### Static catalogue (formerly `WithSkillSet`)

`WithSkillSet` is preserved as a sugar over `WithSkillProvider`. Zero
migration needed:

```go
// v0.4 and v0.5 both work
sdk.New(
    sdk.WithDefaultAgent(...),
    sdk.WithSkillSet(sdk.SkillSet{
        "code-review": {Source: sdk.SkillFromPath{Path: "..."}},
    }),
)
```

The built-in `SkillSet` type now implements both `SkillProvider` and
`SkillCatalog`, so `Admin.ListSkills` keeps working.

#### Public store (no tenant)

```go
type PublicStore struct{ API *PublicAPIClient }

func (p *PublicStore) GetSkills(ctx context.Context, keys []string) (map[string]sdk.Skill, error) {
    return p.API.BatchGet(ctx, keys)
}

sdk.New(
    sdk.WithDefaultAgent(...),
    sdk.WithSkillProvider(&PublicStore{API: client}),
)

// Users explicitly list which keys they want per Run:
sdk.Run(ctx, prompt, sdk.WithSkills(sdk.Key("code-review"), sdk.Key("security-audit")))
```

`Admin.ListSkills` returns `SkillSyncUnsupported` because public
stores don't implement `SkillCatalog`. The host UI is expected to use
the store's own browse surface for discovery.

#### Multi-tenant store (with tenant-mandatory required skills)

```go
type TenantStore struct{ Store *MyStoreClient }

func (p *TenantStore) GetSkills(ctx context.Context, keys []string) (map[string]sdk.Skill, error) {
    id, _ := sdk.CallerIdentityFromContext(ctx)

    fetched, err := p.Store.BatchGet(ctx, id.TenantID, keys)
    if err != nil {
        return nil, err
    }
    required, _ := p.Store.RequiredFor(ctx, id.TenantID)

    out := make(map[string]sdk.Skill, len(fetched)+len(required))
    for _, s := range fetched  { out[s.Key] = s }
    for _, s := range required { out[s.Key] = s }
    return out, nil
}
```

A single `GetSkills` call covers BOTH "give me the keys the user
asked for" AND "also inject these tenant-mandatory skills". The SDK
adds every returned `Skill` to the run's selected set, regardless of
whether its key was in the request.

#### Path scan (deployment-managed skills)

For "every subdirectory under `/opt/skills/` is a skill":

```go
skills, err := sdk.LocalSkillsFromDir("/opt/skills",
    sdk.WithDirSkillKeyPrefix("team/"),  // optional; produces "team/<dir>" keys
    sdk.WithDirIgnore("node_modules"),    // optional ignore list
)
if err != nil { return err }

sdk.New(
    sdk.WithDefaultAgent(...),
    sdk.WithDefaultSkills(sdk.SkillsAsRefs(skills)...),
)
```

`LocalSkillsFromDir` doesn't replace `SkillProvider` — its output is a
slice of inline `Skill` values you feed into `WithDefaultSkills` /
`WithSkills`. Combine it with a remote `SkillProvider` for hybrid
deployments.

#### Hybrid (local-managed + remote store)

```go
local, _ := sdk.LocalSkillsFromDir("/opt/skills")

sdk.New(
    sdk.WithDefaultAgent(...),
    sdk.WithDefaultSkills(sdk.SkillsAsRefs(local)...), // local wins as inline
    sdk.WithSkillProvider(&TenantStore{Store: client}), // remote fills bare keys
)

sdk.Run(ctx, prompt,
    sdk.WithSkills(sdk.Key("store-skill-1"), sdk.Key("store-skill-2")),
)
```

Local skills materialize via `SkillFromPath` (zero IO at run time);
store skills resolve through `GetSkills` with the user's caller
identity in `ctx`.

### 2. `RuntimeServiceManager.ReleaseByLabels`

If you implement `RuntimeServiceManager`, add the new method. The
1-line migration uses the SDK-provided mixin:

```go
import "github.com/agent-dance/agent-adaptor/runtimeservice"

type myMgr struct {
    runtimeservice.NoopReleaseByLabels  // ← add this line

    // ... existing fields ...
}

// existing Ensure / ReleaseByRun unchanged
```

When you're ready to support label-based release for real, remove the
embedding and write the body. Typical implementation:

```go
func (m *myMgr) ReleaseByLabels(ctx context.Context, labels map[string]string) error {
    // Empty labels map releases nothing — see docs/v0.5.0-host-integration-plan.md §A3.
    if len(labels) == 0 {
        return nil
    }
    matches, err := m.backend.ListByLabels(ctx, labels)
    if err != nil {
        return err
    }
    for _, svc := range matches {
        if err := m.backend.Stop(ctx, svc.ID); err != nil {
            return err
        }
    }
    return nil
}
```

### 3. `ErrSkillsNotEnumerable` removal

If you previously matched on `errors.Is(err, ErrSkillsNotEnumerable)`,
the new equivalent is to inspect `SkillSnapshot.Mode`:

```go
// v0.4
snapshot, err := admin.ListSkills(ctx)
if errors.Is(err, agentadaptor.ErrSkillsNotEnumerable) {
    // ...
}

// v0.5
snapshot, err := admin.ListSkills(ctx)
if err == nil && snapshot.Mode == agentadaptor.SkillSyncUnsupported {
    // ...
}
```

Run-time bare `SkillKey` references that fail to resolve now surface
as `ErrSkillNotFound` (matching v0.4's "key truly missing" path).

## New capabilities cheat-sheet

### `SkillFromArchive` — remote skill bundles

Before v0.5, every host using a remote skill catalogue had to write
~400 lines of zip/tar handling, content-addressed caching, atomic
extraction, zip-slip protection, and decompression-bomb defence.
That stack now ships as built-in:

```go
sdk.Skill{
    Key: "compliance-pack",
    Source: sdk.SkillFromArchive{
        Archive: sdk.ArchiveFromURL("https://store/...", sdk.WithArchiveHeader("Authorization", "Bearer "+token)),
        Format:  sdk.SkillArchiveZip,           // "" for magic-byte detection
        Subpath: "compliance/v3",                // optional — skip wrapping directory
        Fingerprint: "sha256:abc123",            // optional — cache key (auto-computed if empty)
    },
}
```

For complete control over the byte stream (custom auth, POST bodies,
streaming decompression), use `Archive: func(ctx) (io.ReadCloser, error)`
directly. See [`v0.5.0-host-integration-plan.md`](./v0.5.0-host-integration-plan.md) §A2 for the architectural rationale.

### `PendingTracker` — long-session HITL UI

Use the snapshot helper for one-off lookups and the tracker for live
UIs:

```go
// One-off (admin dump, REST handler):
records, _ := recorder.Since(ctx, sessionKey, 0)
pending := sessionrecorder.PendingDecisions(records)

// Live UI (long sessions; O(1) per event):
tracker := sessionrecorder.NewPendingTracker()
for rec := range incoming {
    tracker.Apply(rec)
    if isHITL(rec.Payload.Kind) {
        broadcastPending(tracker.Snapshot())
    }
}
```

The tracker is thread-safe; one writer + many readers is the typical
pattern.

## Naming glossary (the things hosts get wrong)

We added [`docs/usage-guide.md` §7-§8](../usage-guide.md) with the
canonical definitions. The TL;DR:

| Concept | Type / shape | Purpose |
|---|---|---|
| `ThreadID` | string (host) | UI-facing conversation identifier |
| `SessionKey = (Namespace, Key)` | `SessionRequest{Namespace, Key, ...}` (NOT a real type) | Stable input to `SessionStore.Resolve`. The SDK does not export a `SessionKey` type — that's the canonical mistake hosts make |
| `SessionID` | string (SDK-allocated) | Driver-level resume handle |
| `RunID` | string (SDK-allocated, per `Start()`) | Single execution instance |

If your code names a host-side history store `SessionStore`, you're
about to collide with `agentadaptor.SessionStore`. Rename it
`ThreadHistoryStore` and use `pkg/hosttools/sessionrecorder` for the
actual storage.

## Checklist for upgrading

- [ ] Update `go.mod` to `v0.5.0`
- [ ] Rewrite your `SkillProvider.List` as `GetSkills` (cookbook §1)
- [ ] If you use `errors.Is(err, ErrSkillsNotEnumerable)`, switch to `SkillSnapshot.Mode == SkillSyncUnsupported`
- [ ] If you have a custom `RuntimeServiceManager`, embed `runtimeservice.NoopReleaseByLabels` (cookbook §2)
- [ ] If you derive HITL pending lists in a loop, switch to `sessionrecorder.PendingTracker`
- [ ] Audit your repo for `SessionStore` typename collisions (cookbook §4 in `usage-guide.md`)
- [ ] (Optional) Port any in-house URL-fetching skill plumbing to `SkillFromArchive`
- [ ] (Optional) Use the new typed-error predicates (`IsRunEnded`, `IsDecisionExpired`, etc.)
